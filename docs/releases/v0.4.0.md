# Trestl v0.4.0

This release makes work-item hierarchies easier to organize, connects milestones to their work, and fills gaps in the API and CLI.

## Hierarchies

- Choose or clear an existing item's parent from its properties, convert items to subtasks, and set a parent for selected list items. Self-parenting and cycles are rejected. ([#23](https://github.com/saynain/trestl/issues/23))
- Filter for top-level items, items with subtasks, or a selected parent's subtasks. Show a collapsible hierarchy and completed-subtask counts, or summarize subtasks on their parent's board card. ([#27](https://github.com/saynain/trestl/issues/27))

## Milestones

- Assign work items to milestones within their project. Review linked items and completion progress in milestone details, the roadmap, and Gantt, and filter work by milestone or by missing milestone. ([#24](https://github.com/saynain/trestl/issues/24))
- Set milestone assignments from the CLI and inspect progress in milestone listings.

## CLI and API

- Create or update items with `--parent` / `--no-parent`, remove relations, delete items with an expected revision, and use command-specific help. Use a parent work item as an umbrella rather than introducing a separate epic type. ([#25](https://github.com/saynain/trestl/issues/25))
- Read incoming and outgoing relations with `GET /api/v1/items/{id}/relations`, including display information for related items. Relation creation returns the created relation and its ID. ([#26](https://github.com/saynain/trestl/issues/26))
- `PATCH /api/v1/items/{id}` now returns `{ "item": ... }`, including the updated revision. API clients that previously read the item directly from the response must read `response.item`. Item creation still returns the item directly. Update the CLI and Raycast extension alongside the server.

## Release checks

The `v0.4.0` branch runs the same continuous-integration checks as `main`. The release is prepared on that branch; publishing packages, container images, and a release tag remains a separate step.
