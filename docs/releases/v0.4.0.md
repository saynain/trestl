# Trestl v0.4.0

This release introduces Trestl Desktop, makes work-item hierarchies easier to organize, connects milestones to their work, and fills gaps in the API and CLI.

## Hierarchies

- Choose or clear an existing item's parent from its properties, convert items to subtasks, and set a parent for selected list items. Self-parenting and cycles are rejected. ([#23](https://github.com/saynain/trestl/issues/23))
- Filter for top-level items, items with subtasks, or a selected parent's subtasks. Show a collapsible hierarchy and completed-subtask counts, or summarize subtasks on their parent's board card. ([#27](https://github.com/saynain/trestl/issues/27))

## Milestones

- Assign work items to milestones within their project. Review linked items and completion progress in milestone details, the roadmap, and Gantt, and filter work by milestone or by missing milestone. ([#24](https://github.com/saynain/trestl/issues/24))
- Set milestone assignments from the CLI and inspect progress in milestone listings.

## CLI and API

- Create or update items with `--parent` / `--no-parent`, remove relations, delete items with an expected revision, and use command-specific help. Use a parent work item as an umbrella rather than introducing a separate epic type. ([#25](https://github.com/saynain/trestl/issues/25))
- Read incoming and outgoing relations with `GET /api/v1/items/{id}/relations`, including display information for related items. Relation creation returns the created relation and its ID. ([#26](https://github.com/saynain/trestl/issues/26))
- `PATCH /api/v1/items/{id}` now returns `{ "item": ... }`, including the updated revision. API clients that previously read the item directly from the response must read `response.item`. Item creation still returns the item directly. Update the CLI and Raycast extension alongside the server.

## Desktop application

Trestl is now available as a Tauri v2 desktop application for macOS (Apple Silicon
and Intel), Windows x64, and Linux x64. The installers include the runtime and a
local PGlite database. No Node.js, Docker, PostgreSQL, or hosted web server is
required. Projects, tasks, roadmaps, and canvases work offline; connected services
still require a network connection.

On macOS, an integrated title bar with native traffic lights, system typography,
light/dark appearance, and native menus makes Trestl feel at home. Native save
dialogs, window restoration, single-instance focus, and clean database shutdown
are included.

Choose the installer matching your platform from this release's assets:

- macOS: `aarch64-apple-darwin.dmg` for Apple Silicon or `x86_64-apple-darwin.dmg` for Intel.
- Windows: `x86_64-pc-windows-msvc.exe` or `.msi`.
- Linux: `x86_64-unknown-linux-gnu.AppImage`, `.deb`, or `.rpm`.

Names begin with `trestl-desktop-0.4.0-`. Verify desktop downloads against
`desktop-SHA256SUMS`; the CLI continues to use its separate `SHA256SUMS` file.

## Data and upgrades

Create a local account on first launch. Desktop storage is separate from any
hosted installation. Transfer projects using project export/import. Quit the app
before backing up its full data folder, including the database and `app-secret`.
Use **Trestl → Check for Updates…** to download signed updates and restart when
ready. The app also checks in the background. Linux `.deb`/`.rpm` installations
use their package manager or a newer downloaded package.

The web image remains available at `ghcr.io/saynain/trestl:v0.4.0`. The CLI archive
is attached to this release and mirrored at `ghcr.io/saynain/trestl-cli:v0.4.0`.
CLI/Raycast connections use hosted installations; they do not connect to the
private desktop service.

See the [desktop guide](https://github.com/saynain/trestl/blob/v0.4.0/docs/desktop.md)
for system requirements, local storage locations, installation, and backups.
