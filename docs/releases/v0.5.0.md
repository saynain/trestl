# Trestl v0.5.0

Integration candidate for issues #28–#32 and live canvas collaboration. This branch has not been published as a release.

- Reference canvases from work item descriptions, comments, and project descriptions.
- Reference milestones from work item descriptions and comments without assigning work to them.
- Add dependencies using **Blocked by**, alongside **Blocks** and **Related to**.
- Find current-project work items first in relationship and reference pickers, while keeping cross-project results available.
- Inspect the running server version and compare it with the latest release in Administration.

## Live canvas collaboration

Draw together on the same project canvas with live edits, named cursors, selections,
and an editor count. **Share** copies a link for colleagues who already have project
access. Shapes, text, images, titles, backgrounds, and grid settings synchronize;
zoom, pan, appearance, and undo history remain personal.

The embedded Excalidraw editor connects to Trestl's existing Fastify server over
WebSockets. The server merges changed elements, saves the canvas in the existing
database, then broadcasts the committed scene. **Saved** confirms that commit.
Edits to different shapes are retained; concurrent edits to the same shape resolve
to one complete element using Excalidraw versions, without character-level text
merging. Clients retain pending edits in an open tab and automatically reconnect.
Unsaved edits do not survive closing the tab or a browser crash.

No separate service or paid account is required. Keep one Trestl app instance and
configure the reverse proxy to forward WebSocket upgrades on `/api/`. The current
limits are 40 open editors per canvas, 8 MiB per scene, and 20,000 elements including
deletion tombstones. Full scene snapshots are broadcast, so large canvases cost more
to synchronize. The public website demo remains local to each visitor.

See [live canvas collaboration](../canvas-collaboration.md) for setup, the edit and
reconnect flow, access checks, and operational limits.

## Test locally

From a checkout of `v0.5.0`, install dependencies with `pnpm install --frozen-lockfile` and start `pnpm dev`. The development UI runs at `http://127.0.0.1:5173` by default. For a second instance, use `PORT=4318 WEB_PORT=5174 pnpm dev` and open `http://127.0.0.1:5174`.

Use a separate checkout without an existing `.env` or `.data` directory to get an isolated local database. Create a local test account on the first-run screen; optionally enable demo data. Do not point a test checkout at a production database.

## Manual checks

1. Create two projects, each with work items. In a work item, open **Add relationship**: current-project items should appear first and other projects should remain available.
2. Select **Blocked by**, choose another item, and save. Confirm the inverse **Blocks** display on the other item and persistence after reload.
3. Create a canvas. Type `!` in a work item description or comment, choose the canvas, save, and open its link. Repeat in the project description.
4. Create a milestone. Type `%` in a work item description or comment, choose the milestone, and save. Follow its link and verify that the work item's **Milestone** property and milestone progress remain unchanged.
5. Open **Administration → Server version**. Check the installed version/build identifier and refresh the release check. An inaccessible release source should show an unavailable status while retaining the installed version.

6. Open the same canvas in two separate signed-in browser profiles with project access. Draw a different shape in each, move a shape, edit text, and rename the canvas. Confirm both sessions show the changes, cursors, selections, and **Saved**. Undo a local shape edit and confirm the other person's separate shape remains. Reload and verify the saved drawing and updated canvas references.
7. Disconnect one editor, make edits in both sessions, reconnect, and confirm edits to different shapes survive. Keep the disconnected tab open until it reports **Saved**. Verify that a user without project access cannot open the shared link.

Automated checks: `pnpm test`, `pnpm build`, and `pnpm desktop:version`.
